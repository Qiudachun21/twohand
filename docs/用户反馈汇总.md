## 一、反馈管理说明

### 1.1 反馈来源分类

| 来源类型 | 说明 | 录入方式 |
|----------|------|----------|
| 用户访谈 | 一对一深度访谈，了解用户痛点和需求 | 完整录入访谈记录+关键洞察 |
| 问卷调查 | 批量问卷收集定量数据 | 录入统计结果+关键发现 |
| 应用内反馈 | 用户通过「意见反馈」入口提交的问题 | 按问题类型分类录入 |
| 客服反馈 | 私信/客服渠道收集的用户问题 | 提炼共性问题录入 |
| 竞品分析 | 从竞品用户评价中提炼的共性需求 | 标注来源为「竞品分析」 |
| 产品假设 | 产品经理基于场景分析提出的需求假设 | 标注为「假设」，需后续验证 |

### 1.2 问题分类标准

| 问题类型 | 定义 | 处理优先级 |
|----------|------|-----------|
| 功能缺陷 | 功能无法使用或与预期不符 | P0（立即修复） |
| 体验问题 | 功能可用但操作不便/流程繁琐 | P1（下个版本优化） |
| 需求建议 | 用户提出的新功能/新场景需求 | 录入需求池，评估优先级 |
| 内容问题 | 商品信息/分类/数据不准确 | P1（及时修正） |
| 性能问题 | 页面加载慢/卡顿/崩溃 | P0（立即排查） |
| 其他 | 不属于以上分类的反馈 | 评估后分类 |

### 1.3 共性问题判断标准

- **共性问题：** 同一问题被≥3个不同用户提及，或在问卷中选择率≥20%
- **个别问题：** 仅1-2个用户提及，或为个性化场景需求

## 二、V1.0 阶段需求假设（待验证）

V1.0为MVP版本，暂无真实用户反馈。以下为产品设计阶段基于场景分析提出的需求假设，需在V1.0上线后通过用户反馈验证：

### 假设 #001：学生教材采购痛点

| 项目 | 内容 |
|------|------|
| 假设描述 | 大学生每学期需购买5-10本教材，新书价格高（300-500元/学期），逐本搜索购买时间成本高 |
| 假设来源 | 产品场景分析+个人经验 |
| 验证方式 | 用户调研问卷+书单匹配功能使用率数据 |
| 当前状态 | 待验证 |
| 对应功能 | 书单批量匹配、二手书专区 |

### 假设 #002：毕业季清仓需求

| 项目 | 内容 |
|------|------|
| 假设描述 | 大四毕业生有大量教材/生活用品需处理，毕业季时间窗口短（1-2周），大量物品最终被丢弃 |
| 假设来源 | 产品场景分析 |
| 验证方式 | 毕业季发布量数据+用户访谈 |
| 当前状态 | 待验证 |
| 对应功能 | 发布页（批量发布预留）、毕业季专题（V1.1规划） |

### 假设 #003：同校信任需求

| 项目 | 内容 |
|------|------|
| 假设描述 | 通用二手平台卖家身份不明，存在欺诈风险，学生更倾向于与同校学生交易 |
| 假设来源 | 竞品分析+场景分析 |
| 验证方式 | 身份认证率+用户调研 |
| 当前状态 | 待验证 |
| 对应功能 | 学号认证、校区标签、卖家信息展示 |

### 假设 #004：校内线下交易可行性

| 项目 | 内容 |
|------|------|
| 假设描述 | 高校校园是封闭场景，同校学生间线下见面交易（宿舍楼下/食堂/教学楼）自然可行，无需物流和支付 |
| 假设来源 | 场景分析 |
| 验证方式 | 私信沟通率+线下成交率（估算）+用户访谈 |
| 当前状态 | 待验证 |
| 对应功能 | 私信系统、校区标签、交易方式（自提/宿舍配送） |

### 假设 #005：留言式聊天可满足需求

| 项目 | 内容 |
|------|------|
| 假设描述 | 二手交易沟通为低频异步场景，买卖双方通常「发消息→等回复→再沟通」，留言式聊天可满足基本需求 |
| 假设来源 | 场景分析+MVP裁剪决策 |
| 验证方式 | 私信回复率+用户反馈（是否抱怨消息不及时） |
| 当前状态 | 待验证 |
| 对应功能 | 私信系统（留言式） |

### 3.2 访谈记录

> V1.0阶段暂无用户访谈记录。V1.0上线后计划开展以下访谈：
>
> 1. **买家访谈（5人）：** 大一/大二学生，了解教材采购习惯和痛点
> 2. **卖家访谈（3人）：** 大四毕业生，了解毕业清仓需求和发布体验
> 3. **双向用户访谈（2人）：** 大二/大三学生，了解闲置物品交易习惯
>
> 访谈提纲：
> - 你每学期大概买几本教材？通常通过什么渠道购买？
> - 你有没有在二手平台买过东西？体验如何？
> - 如果有一个同校二手交易平台，你最希望它有什么功能？
> - 你觉得书单批量匹配功能对你有帮助吗？为什么？
> - 你更倾向于线上支付还是线下见面交易？为什么？

## 四、反馈处理流程

```
收到反馈 → 分类录入（问题类型+频次） → 评估优先级
    ↓
P0功能缺陷/性能问题 → 立即修复 → 更新状态 → 通知用户
    ↓
P1体验问题/内容问题 → 录入需求池 → 排期下个版本 → 更新状态
    ↓
P2需求建议 → 录入需求池 → 评估价值/成本 → 确定优先级 → 排期
    ↓
共性问题（≥3人提及） → 提升优先级 → 重点关注
个别问题 → 记录归档 → 持续观察是否升级为共性
```

## 五、反馈数据统计模板

V1.0上线后，每月统计以下反馈数据：

| 统计维度 | 指标 | 统计方式 |
|----------|------|----------|
| 反馈总量 | 本月收到反馈总数 | 计数 |
| 问题分布 | 各问题类型占比 | 分类统计 |
| 共性问题TOP5 | 本月提及最多的5个问题 | 按频次排序 |
| 处理率 | 已处理反馈/总反馈 | 百分比 |
| 平均处理时长 | 从反馈录入到处理完成的平均时间 | 平均值 |
| 用户满意度 | 反馈处理后用户满意度（如有评分） | 平均值 |
| 需求转化率 | 反馈转化为需求池需求的比例 | 百分比 |
