## 优先级定义

| 优先级 | 定义 | 判断标准 |
|--------|------|----------|
| P0 核心必做 | 不做则产品无法成立或核心闭环断裂 | 影响核心交易流程、用户无法完成主要任务 |
| P1 重要优化 | 显著提升用户体验或业务效率，但不影响核心闭环 | 高频使用场景、用户痛点明确、投入产出比高 |
| P2 锦上添花 | 体验加分项，有则更好，无则不影响使用 | 低频场景、个性化需求、运营辅助功能 |
| P3 暂不考虑 | 当前阶段不做，记录原因避免重复讨论 | 技术成本过高、需求验证不足、与MVP定位不符 |

## 四、V1.0 需求取舍说明

V1.0 MVP版本严格遵循「最小可用产品」原则，核心目标是跑通「发布闲置 → 搜索/匹配 → 联系交易」完整流程，验证校园二手交易需求。

**做了什么：**
- 核心交易闭环全链路覆盖（发布→浏览→搜索→详情→联系→沟通）
- 书单匹配核心差异化功能完整实现
- 基础用户体系（认证/收藏/书单/私信）
- 清新校园风UI，移动端优先体验

**没做什么（及原因）：**
- 在线支付：涉及资质合规，校园场景线下交易自然可行
- 实时通讯：留言式可满足MVP需求，降低开发复杂度
- 后端服务：用localStorage验证需求，验证通过后再投入后端开发
- 评价/风控：同校身份降低风险，用户量增长后再系统化
